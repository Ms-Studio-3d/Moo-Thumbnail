# Moo-Thumbnail — Portable v1.0.1

برنامج Windows مستقل لاستخراج صور YouTube المصغّرة وحفظها بصيغة JPG.

## الاستخدام من دون تثبيت

1. حمّل `Moo-Thumbnail-1.0.1-Portable-x64.exe` من قسم Releases.
2. ضع الملف في مجلد يسمح بالكتابة، مثل مجلد خاص بك أو وحدة USB.
3. افتح EXE مباشرة. لا يحتاج Node.js أو npm أو صلاحيات مسؤول.
4. ألصق رابط فيديو واضغط «استخراج الصور».
5. اختر جودة متاحة ثم «حفظ الصورة» وحدد مكان الحفظ.
6. استخدم «نسخ الرابط» أو «فتح المجلد» عند الحاجة.

المتطلبات: Windows 10/11 بنواة x64 واتصال إنترنت لاستخراج الصور.
البرنامج لا يحمّل الفيديو ولا يرفع ملفاتك إلى خادم. يتصل بخادم صور YouTube فقط.
أسماء الجودات تعبّر عن ملفات YouTube؛ الأبعاد المعروضة مقاسة من الصورة نفسها.
عدم توفر جودة لا يعني وجود عطل في البرنامج. قد لا تكون كل الجودات موجودة للفيديو.

## بيانات النسخة المحمولة

ينشئ البرنامج مجلد `Moo-Thumbnail-data` بجوار ملف EXE لتخزين بيانات تشغيل Chromium.
انقل المجلد مع EXE إذا أردت نقل بياناته، أو احذفه والبرنامج مغلق لإعادة ضبطه.
تُفك ملفات التشغيل مؤقتًا أثناء التشغيل ثم يغلقها المشغّل المحمول عند الخروج؛ لا توجد عملية تثبيت أو اختصارات تلقائية.
الصور تُحفظ فقط في المكان الذي تختاره. تغيير مكان EXE لا ينقل الصور المحفوظة.
الإصدار غير موقّع بشهادة تجارية. قد يعرض Windows رسالة ناشر غير معروف؛ لا توجد شهادة أو سمعة SmartScreen مضمونة.

## التشغيل والبناء من المصدر

هذه الخطوات للمطور أو GitHub Actions فقط؛ المستخدم النهائي يفتح EXE مباشرة.

ثبّت Node.js 24 LTS، ثم افتح `run-source.bat` للتشغيل أو `build-portable.bat` للبناء.
الأوامر المكافئة:

```powershell
npm ci
npm test
npm run test:smoke
npm start
npm run dist
```

البناء داخل `dist/`. يعمل `npm run test:live` على أربعة فيديوهات عامة ويختبر تنزيل الصور وأبعادها وحفظ كل جودة متاحة. يحتاج إنترنت وقد تتغير الصور بمرور الوقت.

## النشر على GitHub خطوة بخطوة

1. أنشئ مستودعًا باسم `Moo-Thumbnail` على حسابك.
2. ارفع محتويات مجلد المشروع، بما فيها الملفات المخفية `.github` و`.gitignore` وملف `package-lock.json`. لا ترفع `node_modules` أو `dist` أو بيانات الاختبار.
3. أسهل طريقة للحفاظ على الملفات المخفية هي GitHub Desktop: أضف مجلد المشروع كمستودع محلي، نفّذ Commit ثم Publish repository.
4. افتح تبويب Actions وانتظر نجاح سير العمل `Test, build and release portable Windows app`.
5. يمكنك تنزيل النسخة المبنية من Artifacts بعد نجاح البناء.
6. لنشر الإصدار: افتح Releases ثم Draft a new release، وأنشئ Tag جديدًا `v1.0.1` على الفرع الذي رفعت إليه المشروع، ثم Publish release.
7. انتظر تشغيل Actions؛ سيُرفق ملف Portable EXE و`SHA256SUMS.txt` بالإصدار نفسه تلقائيًا. يمكن إعادة تشغيله لتحديث المرفقات إذا فشل الرفع.
8. اختبر ملف EXE الذي بُني على GitHub على جهاز Windows آخر بحساب عادي قبل الإعلان عنه للناس.

يمكن أيضًا دفع Tag `v1.0.1` عبر Git ليُنشئ سير العمل الإصدار تلقائيًا.
لا تحتاج مفتاح GitHub شخصيًا؛ يُستخدم `GITHUB_TOKEN` الخاص بسير العمل.
يجب أن تسمح سياسة المستودع/المؤسسة بكتابة محتويات Releases بواسطة Actions.
أي إصدار لاحق يجب أن تتطابق فيه نسخة `package.json` وTag، مثل `1.0.1` و`v1.0.1`.

## الاختبارات والحدود

راجع `TEST-REPORT.md` لمعرفة ما اختُبر فعليًا وما بقي خارج التحقق.
اختبار الحفظ المحلي ونجاح البناء لا يثبتان التوافق مع كل جهاز Windows أو نجاح Actions قبل تشغيله في مستودعك.
Moo-Thumbnail أداة مستقلة غير تابعة لـ YouTube. استخدم الصور بما يتوافق مع حقوق أصحابها.
